Reading the lecturer's EM code

The lecturer's EM demo is four short R functions. Each line is one formula you already know: the joint \(\pi_kf_k(x_i)\), Bayes' rule, a column average, a weighted mean, and \(\ell=\sum_i\log\sum_k\pi_kf_k(x_i)\). The win: given her code and a printout, say what every line computes and reproduce one iteration's numbers by hand to 2 d.p.

Why this matters for 10 Nov: the lecturer said the exam asks you to read and interpret R code and output, never to write it, and named her QMD demo files as prep, EM-updated.qmd among them. Past EM questions already printed EM runs and asked "which estimate, and why?" plus a responsibility by hand (2020). Expect this year's EM question to show mixture.EM or its Poisson twin from tute week 7 and ask what a line does, what a number means, or what's wrong.

Assumed: responsibilities and M/rowSums(M) (Lesson 16), the EM loop and multiple starts (Lesson 17), the M-step formulas \(\hat\pi_k=\frac1n\sum_i\gamma_{ik}\), \(\hat\mu_k=\sum_i\gamma_{ik}x_i/\sum_i\gamma_{ik}\) (Lesson 18). Notation: \(\gamma_{ik}=P(Z_i=k\mid X_i=x_i,\theta^0)\), which the code stores as P_ik[i, k]. All R output below was produced by running the lecturer's functions.   • sample(1:3, NUM.SAMPLES, replace=TRUE, prob = pi.true.2): 200 independent labels with \(P(Z_i=k)=\pi_k\), i.e. \(Z_i\sim\text{Categorical}(0.2,0.3,0.5)\). replace=TRUE is essential: without it you can't draw 200 values from 3.
  • mu.true.2[Z]: a length-200 vector holding each draw's own component mean. rnorm is vectorised, so draw \(i\) uses mean mu.true.2[Z[i]]. That one line is \(X_i\mid Z_i=k\sim N(\mu_k,\sigma_k^2)\) for all \(i\).
  • sd=sqrt(...): R's rnorm and dnorm take the standard deviation; the model is written with variances.
  • table(Z): 48/51/101 out of 200, close to 0.2/0.3/0.5. These true labels are kept only to check the clustering later (§6); EM never sees them.

Tute week 7 builds its Poisson data in a loop instead: Z[i] <- rbinom(1,1, pi_2), then if(Z[i] == 0) X[i] <- rpois(1, lambda_1) else X[i] <- rpois(1, lambda_2). Same model, labels coded 0/1 instead of 1/2.

1. A classmate rewrites the simulation as X.2 <- rnorm(NUM.SAMPLES, mean=mu.true.2[Z], sd=sigma2.true.2[Z]). What changes?

rnorm(n, mean, sd) takes the SD. Passing sigma2.true.2[Z] \(=2\) gives SD 2, variance \(2^2=4\): the components overlap even more than intended. The lecturer writes sd=sqrt(sigma2.true.2[Z]) so SD \(=\sqrt2\), variance 2. The same SD-vs-variance slip in dnorm inside the EM code makes it fit a different model.

2 · The four functions, mapped to the maths

The code as it appears in EM-updated ("EM R implementation"), comments trimmed. The model: three Normals with known variance 2, unknown \(\pi_k\) and \(\mu_k\).

mixture.EM <- function(X, pi.init, mu.init, epsilon=1e-5, max.iter=100) {
  pi.curr = pi.init
  mu.curr = mu.init
  log_liks = c()
  log_liks = c(log_liks, compute.log.lik(X, pi.curr, mu.curr)$ill)
  delta.ll = 1
  n.iter = 1
  while((delta.ll > epsilon) & (n.iter <= max.iter)){
    EM.out = EM.iter(X, pi.curr, mu.curr)
    pi.curr = EM.out$pi.new
    mu.curr = EM.out$mu.new
    log_liks = c(log_liks, compute.log.lik(X, pi.curr, mu.curr)$ill)
    delta.ll = log_liks[length(log_liks)] - log_liks[length(log_liks)-1]
    n.iter = n.iter + 1
  }
  return(list(pi.curr=pi.curr, mu.curr=mu.curr, log_liks=log_liks))
}

EM.iter <- function(X, pi.curr, mu.curr) {
  # E-step
  prob.x.z = compute.prob.x.z(X, pi.curr, mu.curr)$prob.x.z
  P_ik = prob.x.z / rowSums(prob.x.z)
  # M-step
  pi.new = colSums(P_ik)/sum(P_ik)  # sum(P_ik) is equivalent to sample size
  mu.new = colSums(P_ik*X)/colSums(P_ik)
  return(list(pi.new=pi.new, mu.new=mu.new))
}

compute.log.lik <- function(X, pi.curr, mu.curr) {
  prob.x.z = compute.prob.x.z(X, pi.curr, mu.curr)$prob.x.z
  ill = sum(log(rowSums(prob.x.z)))
  return(list(ill=ill))
}

compute.prob.x.z <- function(X, pi.curr, mu.curr) {
  L = matrix(NA, nrow=length(X), ncol=length(pi.curr))
  for(k in seq_len(ncol(L))) {
    L[, k] = dnorm(X, mean=mu.curr[k], sd=sqrt(2))*pi.curr[k]
  }
  return(list(prob.x.z=L))
}

Two R facts make the one-liners work:

  • Recycling down columns. R stores a matrix column by column. prob.x.z / rowSums(prob.x.z) divides an \(n\times K\) matrix by a length-\(n\) vector, so the vector is reused down each column: entry \([i,k]\) is divided by element \(i\), the row-\(i\) total. Same for P_ik*X: entry \([i,k]\) is multiplied by \(x_i\).
  • colSums sums over \(i\) (down a column, one result per component); rowSums sums over \(k\) (across a row, one result per observation).

pi.new = colSums(P_ik)/sum(P_ik) is the same as colMeans(P_ik) or colSums(P_ik)/length(X), because sum(P_ik) \(=n\). Tute week 7's Poisson version is identical with renamed variables: w.curr for \(\pi\), lambda_curr for \(\lambda\), w.new, lambda_new, and dpois(X, lambda_curr[k])*w.curr[k] in place of dnorm. The \(\lambda\) update is the same weighted mean, because \(\hat\lambda_k=\sum_i\gamma_{ik}x_i/\sum_i\gamma_{ik}\) too.

2. In compute.prob.x.z, what is L[, k] = dnorm(X, mean=mu.curr[k], sd=sqrt(2))*pi.curr[k]?

dnorm(X, ...) is vectorised over all \(n\) observations, giving \(f(x_i;\mu_k,2)\) for each \(i\); multiplying by pi.curr[k] gives \(\pi_kf(x_i;\mu_k,2)=P(X_i=x_i\mid Z_i=k)P(Z_i=k)=P(X_i=x_i,Z_i=k)\). The responsibilities (a) need the next line's division by rowSums, and the mixture density (d) is rowSums itself. The loop runs over components, not observations.

Step 1: one entry of prob.x.z from scratch. Row 3, \(x_3=0.9\). The \(N(\mu,2)\) density is \(\frac{1}{\sqrt{4\pi}}e^{-(x-\mu)^2/4}\), and \(\frac1{\sqrt{4\pi}}=0.282095\).

$$\begin{aligned} \texttt{prob.x.z}[3,1]&=0.4\times\tfrac{1}{\sqrt{4\pi}}e^{-(0.9-0)^2/4}\\ &=0.4\times0.282095\times e^{-0.2025}\\ &=0.4\times0.282095\times0.816686\\ &=0.0922\\[6pt] \texttt{prob.x.z}[3,2]&=0.6\times\tfrac{1}{\sqrt{4\pi}}e^{-(0.9-3)^2/4}\\ &=0.6\times0.282095\times e^{-1.1025}\\ &=0.6\times0.282095\times0.332049\\ &=0.0562 \end{aligned}$$

Both match the printout.

Step 2: the E-step row. Divide row 3 by its total:

$$\begin{aligned} \texttt{P\_ik}[3,1]&=\frac{0.0922}{0.0922+0.0562}\\ &=\frac{0.0922}{0.1484}\\ &=0.62\\[6pt] \texttt{P\_ik}[3,2]&=1-0.62\\ &=0.38 \end{aligned}$$

On the FX-82 you can skip Step 1's constant: \(\frac1{\sqrt{4\pi}}\) is the same in both components (equal variances), so it cancels. 0.4e^(−0.81÷4) ÷ (0.4e^(−0.81÷4) + 0.6e^(−2.1²÷4)) → 0.6212. With unequal variances the \(1/\sigma_k\) factors would not cancel.

Step 3: the M-step from the column sums.

$$\begin{aligned} \hat\pi_1=\texttt{pi.new}[1]&=\frac{\texttt{colSums(P\_ik)}[1]}{n}\\ &=\frac{2.9289}{6}\\ &=0.49\\[6pt] \hat\mu_1=\texttt{mu.new}[1]&=\frac{\sum_i\gamma_{i1}x_i}{\sum_i\gamma_{i1}}\\ &=\frac{-0.1907}{2.9289}\\ &=-0.07 \end{aligned}$$

The numerator \(-0.1907\) is \(0.9810(-1.4)+0.8952(-0.2)+0.6212(0.9)+0.3646(1.6)+0.0570(3.1)+0.0099(4.3)\), which is what column 1 of P_ik*X sums to.

Step 4: \(\ell\) before and after. ill at \(\theta^0\) is the sum of the logs of the six row totals:

$$\begin{aligned} \ell(\theta^0)&=\log0.0705+\log0.1248+\log0.1484\\ &\quad+\log0.1632+\log0.1790+\log0.1120\\ &=-12.36 \end{aligned}$$

After one iteration ill is \(-12.22\): up, as EM guarantees. (FX-82: ln(0.0705×0.1248×0.1484×0.1632×0.1790×0.1120) is one log instead of six.)

3. From the printed prob.x.z, compute P_ik[4, 1] (2 d.p.). Which component would observation 4 be assigned to?

$$\begin{aligned}\texttt{P\_ik}[4,1]&=\frac{0.0595}{0.0595+0.1037}\\&=\frac{0.0595}{0.1632}\\&=\textbf{0.36}\end{aligned}$$ Matches the printed 0.3646. It's below 0.5, so \(x_4=1.6\) goes to component 2. With equal variances the boundary would be the midpoint 1.5 if the weights were equal; 1.6 is just past it towards \(\mu_2^0=3\), and component 2 also has the larger weight 0.6, so both effects favour component 2.

4. From the printout, compute mu.new[2] (2 d.p.) and say what kind of average it is.

$$\begin{aligned}\hat\mu_2&=\frac{\texttt{colSums(P\_ik*X)}[2]}{\texttt{colSums(P\_ik)}[2]}\\&=\frac{8.4907}{3.0711}\\&=\textbf{2.76}\end{aligned}$$ A weighted mean of all six \(x_i\), each weighted by its responsibility for component 2. It moved down from 3 because the points near 1 have sizeable component-2 weights (0.38, 0.64) and drag it left. Dividing by sum(P_ik) \(=6\) instead would give 1.42, a bug (§7).

5. P_ik is \(6\times2\) and X has length 6. What is entry [i, k] of P_ik*X?

* is elementwise. R reads the matrix column by column, and the length-6 X fits each column exactly, so column \(k\) becomes \((\gamma_{1k}x_1,\dots,\gamma_{6k}x_6)\). For instance [1,1] \(=0.9810\times(-1.4)=-1.3734\). colSums then gives \(\sum_i\gamma_{ik}x_i\) (c), the numerator of \(\hat\mu_k\). The matrix product would be t(P_ik) %*% X.

6. (Retrieval: responsibilities, Lesson 16.) Without the printout: \(\pi^0=(0.4,0.6)\), \(\mu^0=(0,3)\), common variance 2. Compute \(P(Z_3=1\mid X_3=0.9,\theta^0)\) (2 d.p.).

The \(\frac1{\sqrt{4\pi}}\) cancels (same variance in both components): $$\begin{aligned}0.4e^{-0.9^2/4}&=0.4e^{-0.2025}\\&=0.326675\\ 0.6e^{-(0.9-3)^2/4}&=0.6e^{-1.1025}\\&=0.199224\\ \gamma_{31}&=\frac{0.326675}{0.326675+0.199224}\\&=\frac{0.326675}{0.525899}\\&=\textbf{0.62}\end{aligned}$$ The divisor in the exponent is \(2\sigma^2=4\), not 2: the model's 2 is the variance. Using \(e^{-(x-\mu)^2/2}\) gives 0.77, the answer for variance 1.

Extension: unknown variances. The demo fixes \(\sigma^2=2\). If the variances were free, \(\hat\sigma_k^2=\sum_i\gamma_{ik}(x_i-\hat\mu_k)^2/\sum_i\gamma_{ik}\) (Lesson 18) would be one more M-step line, and dnorm would use sd=sqrt(sigma2.curr[k]). In the lecturer's style:

> sigma2.new = rep(NA, 2)
> for(k in 1:2) sigma2.new[k] = sum(P_ik[,k]*(X-mu.new[k])^2)/sum(P_ik[,k])
> round(sigma2.new, 4)
[1] 1.4046 1.9113

Note mu.new, not mu.curr: the variance update is centred at the new mean, because the joint maximiser of \(Q\) sets \(\mu_k\) first and the \(\sigma_k^2\) equation then contains \(\hat\mu_k\).

4 · The loop, the stopping rule and the trace

Read mixture.EM top to bottom:

  1. log_liks starts with \(\ell(\theta^0)\), before any EM step.
  2. delta.ll = 1 is a dummy value that lets the while loop start.
  3. Each pass: one E-step + M-step (EM.iter), overwrite pi.curr, mu.curr, append the new \(\ell\), set delta.ll \(=\ell_{\text{new}}-\ell_{\text{old}}\), add 1 to n.iter.
  4. The loop continues while both delta.ll > epsilon and n.iter <= max.iter. It stops at the first pass where the gain is \(\le\epsilon\), or after max.iter passes.

So length(log_liks) \(=\) (number of EM iterations) \(+1\), and at most max.iter + 1. No abs() is needed: for correct EM, \(\ell\) never falls, so delta.ll \(\ge0\). The stopping rule is on the incomplete log-likelihood, as on EM slide 16.

7. The run above returned 26 values in log_liks. Why did the loop stop, and how many EM iterations ran?

The first entry is \(\ell(\theta^0)\), computed before the loop, so 26 values means \(26-1=25\) EM iterations. With max.iter=100, hitting the cap would leave 101 values. So the loop ended because the 25th gain was \(\le\epsilon=10^{-5}\). (The printout rounds to 4 d.p., so the last few gains look like 0.)

8. (Retrieval: AIC, Lesson 3.) The lecturer's three-component, known-variance model has \(\theta=(\pi_1,\pi_2,\mu_1,\mu_2,\mu_3)\). Its best run on X.2 (§5) ends with ill \(=-460.7521\). Compute AIC \(=-2\ell+2p\) (2 d.p.).

$$\begin{aligned}p&=5\quad(\pi_3=1-\pi_1-\pi_2\text{ is not free})\\ \text{AIC}&=-2(-460.7521)+2(5)\\&=921.5042+10\\&=\textbf{931.50}\end{aligned}$$ pi.curr stores three proportions, but only two are free parameters: the qmd says so explicitly. The variances are known (2), so they're not counted. AIC is how you'd compare, say, \(K=2\) against \(K=3\): the larger model always has higher \(\ell\), so \(\ell\) alone can't choose \(K\).

Reading it, in exam order:

  • Report EM1: its final incomplete log-likelihood, −460.75, is the highest. The MLE maximises \(\ell\), so that is the comparison. The estimates \(\hat\pi=(0.26,0.34,0.40)\), \(\hat\mu=(-2.33,0.66,2.91)\) match the lecturer's reported values.
  • EM3 is label-switched. Its means are in reverse order (3.46, 1.50, −2.11): its "component 1" is EM1's component 3. Compare runs by \(\ell\) and by the set of fitted components, never position by position.
  • The first three runs all hit max.iter: length(log_liks) \(=101=\) max.iter \(+1\). They stopped on the iteration cap, not on epsilon. EM3 was still climbing. With overlapping components the likelihood is flat and EM crawls. Rerunning with max.iter=1000 (output below) shows all three reach the same \(\ell=-460.7518\), EM3 with its labels reversed. So the gap −461.33 vs −460.75 here comes from stopping early, not from a different local maximum.
  • EM4 is stuck. With \(\mu_1^0=\mu_2^0=\mu_3^0\) the three columns of prob.x.z are proportional to \(\pi_k^0\), so every row of P_ik is \((0.2,0.3,0.5)\). The M-step returns pi.new \(=(0.2,0.3,0.5)\) unchanged and every mu.new \(=\sum_i0.2x_i/(0.2n)=\bar x=0.7682\). From then on nothing moves: \(\ell\) rose once (means 1 → 0.77), then delta.ll \(=0\) and the loop stopped after 2 iterations. This is a stationary point, not a maximum. Never start with identical components.

L1 and L2 still differ slightly in the 2nd decimal at the same \(\ell\): along a flat ridge, \(\epsilon=10^{-5}\) can stop runs at slightly different points. The lecturer's general rule (slide 17) still holds: run several starts, keep the highest incomplete log-likelihood.

9. In the first printout, which run's estimates do you report, and what is the best reason?

The MLE is the \(\theta\) with the largest \(\ell(\theta)\), so compare the final ill values: \(-460.7521>-460.7533>-461.3282\), and EM4's −568.47 is far worse. EM4 "converged" quickly only because it was stuck with equal means. Spread of the means (a) and the starting values (d) are not criteria; in practice you also check the trace rose and that the run didn't just hit max.iter.

10. Why does EM4 (all initial means equal to 1) end with pi.curr \(=(0.2,0.3,0.5)\) and all three means equal to \(\bar x\)?

If \(\mu_1^0=\mu_2^0=\mu_3^0\), then \(f(x_i;\mu_k^0,2)\) is the same for every \(k\), so $$\begin{aligned}\gamma_{ik}&=\frac{\pi_k^0f(x_i;1,2)}{\sum_j\pi_j^0f(x_i;1,2)}\\&=\pi_k^0.\end{aligned}$$ Then \(\hat\pi_k=\pi_k^0\) and \(\hat\mu_k=\sum_i\pi_k^0x_i/(n\pi_k^0)=\bar x\) for every \(k\): the symmetry can never break. (a) is backwards: delta.ll=1 exceeds \(\epsilon=10^{-5}\), so the loop does start.

7 · Spot the bug

The likely exam form: a modified line, some output, "what is wrong and how can you tell?" Three bugs, each run for real on the six points from §3.

Bug A: normalising the wrong way. P_ik = prob.x.z / colSums(prob.x.z).

> B1 = prob.x.z / colSums(prob.x.z)
> round(rowSums(B1), 4)
[1] 0.2050 0.2748 0.4315 0.3594 0.5208 0.2467

Rows no longer sum to 1, so these are not \(P(Z_i=k\mid X_i)\). Worse, colSums has length 2, and recycling it down the 6-row matrix divides the entries alternately by the two column totals. Even a deliberate column normalisation (column \(k\) divided by its own total) is not Bayes' rule: it shares out each component's mass over the observations. Bayes divides \(P(X_i=x_i,Z_i=k)\) by \(P(X_i=x_i)\), a row total. Run as EM, this version gave log_liks \(=-12.3637,\ -12.3107,\ -12.4092\): one rise, then a fall, and the loop stopped.

Bug B: the wrong log-likelihood. Four candidate lines for ill, evaluated at \(\theta^0\):

> sum(log(rowSums(prob.x.z)))
[1] -12.36368
> log(sum(rowSums(prob.x.z)))
[1] -0.2257789
> sum(rowSums(log(prob.x.z)))
[1] -41.53384
> sum(log(prob.x.z))
[1] -41.53384

Only the first is \(\ell(\theta)=\sum_i\log\sum_k\pi_kf_k(x_i)\): sum over \(k\) inside the log (the mixture density), then log, then sum over \(i\). log(sum(...)) logs a sum over \(i\) of densities, which isn't a likelihood of anything. sum(log(prob.x.z)) is \(\sum_i\sum_k\log[\pi_kf_k(x_i)]\): it pretends each point belongs to every component, the complete-data log-likelihood with all indicators set to 1.

Bug C: wrong denominator in the mean update. mu.new = colSums(P_ik*X)/sum(P_ik).

> e = mixture.EM(X, c(0.4,0.6), c(0,3))   # with the buggy EM.iter
> round(e$log_liks, 4)
[1] -12.3637 -13.1776
> round(e$mu.curr, 4)
[1] -0.0318  1.4151

Dividing by \(n=6\) instead of \(N_k\) shrinks each mean towards 0 (\(\hat\mu_2=8.4907/6=1.42\) instead of 2.76). \(\ell\) falls from −12.36 to −13.18, which a correct EM step can never do. Note the trap: the negative delta.ll fails delta.ll > epsilon, so the loop quietly stops after one iteration and looks "converged". Always check the trace is non-decreasing.

11. A student's log_liks is -12.3637 -13.1776 and the function returns. What is the right diagnosis?

EM satisfies \(\ell(\theta^{t+1})\ge\ell(\theta^t)\) from any start (Lesson 17's Jensen argument), so a drop of 0.81 is a coding error, here Bug C. The loop stopped because delta.ll \(=-0.81\) is not \(>\epsilon\): the stopping rule can't tell "no gain" from "a loss". A bad start (c) gives a lower final \(\ell\), never a downhill step. Round-off (d) shows up in the 10th decimal, not the 1st.

12. Which line correctly computes the incomplete log-likelihood from prob.x.z?

\(\ell=\sum_{i=1}^n\log\big[\sum_{k}\pi_kf_k(x_i)\big]\): sum over components inside the log (rowSums gives \(P(X_i=x_i)\)), then the log of each, then add over observations. (b) is \(\sum_i\sum_k\log(\pi_kf_k(x_i))\), the log of a product over \(k\) instead of a sum: −41.53 vs −12.36 here. (c) sums over observations inside the log, mixing up the roles of \(i\) and \(k\).

Setup (fresh data; about 12 marks). The numbers of insurance claims \(X_1,\dots,X_8\) filed by eight small businesses are modelled as a two-component Poisson mixture: \(Z_i\sim\text{Categorical}(\pi_1,1-\pi_1)\), \(X_i\mid Z_i=k\sim\text{Poisson}(\lambda_k)\). An analyst uses the tute week 7 code:

EM.iter <- function(X, w.curr, lambda_curr) {
  prob.x.z = compute.prob.x.z(X, w.curr, lambda_curr)$prob.x.z
  P_ik = prob.x.z / rowSums(prob.x.z)
  w.new = colSums(P_ik)/sum(P_ik)
  lambda_new = colSums(P_ik*X)/colSums(P_ik)
  return(list(w.new=w.new, lambda_new=lambda_new))
}
compute.prob.x.z <- function(X, w.curr, lambda_curr) {
  L = matrix(NA, nrow=length(X), ncol= length(w.curr))
  for(k in seq_len(ncol(L))) {
    L[, k] = dpois(X, lambda_curr[k])*w.curr[k]
  }
  return(list(prob.x.z=L))
}

Full model answer (all parts)

(a) [1 each]

$$\begin{aligned} \texttt{prob.x.z}[i,k]&=P(X_i=x_i,Z_i=k\mid\theta^0)\\ &=w_k^0\,\frac{(\lambda_k^0)^{x_i}e^{-\lambda_k^0}}{x_i!}\\[6pt] \texttt{P\_ik}[i,k]&=P(Z_i=k\mid X_i=x_i,\theta^0)\\ &=\frac{w_k^0(\lambda_k^0)^{x_i}e^{-\lambda_k^0}/x_i!}{\sum_{j=1}^2w_j^0(\lambda_j^0)^{x_i}e^{-\lambda_j^0}/x_i!} \end{aligned}$$

i.e. the joint, and the responsibility (= \(E_{Z\mid X,\theta^0}[I(Z_i=k)]\)), at the current values \(\theta^0\).

(b) \(x_4=2\), so \(x_4!=2\):

$$\begin{aligned} \texttt{prob.x.z}[4,1]&=0.6\times\frac{1^2e^{-1}}{2}\\ &=0.6\times0.183940\\ &=0.1104\\[6pt] \texttt{prob.x.z}[4,2]&=0.4\times\frac{6^2e^{-6}}{2}\\ &=0.4\times18\times0.002479\\ &=0.0178\\[6pt] \texttt{P\_ik}[4,1]&=\frac{0.1104}{0.1104+0.0178}\\ &=0.86 \end{aligned}$$
